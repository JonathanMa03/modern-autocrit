\section{Purpose and Scope}

Automated Eligibility Criteria Extraction is a local, browser-based application that converts free-text clinical-trial eligibility criteria into atomic, governed Entity--Attribute--Value (EAV) records. A user may supply either a ClinicalTrials.gov NCT identifier or pasted eligibility text. The application retrieves or accepts the protocol text, segments it into atomic criteria, uses a large language model (LLM) to map each criterion into the terminology library, normalizes categorical and numerical values, validates the mapping, and presents a reviewable table. It also exposes a clinical-distance calculator and a read-only view of the EAV library.

This report documents the current implementation rather than the retired desktop interface. It covers every active architectural layer and the public or workflow-defining functions in the project. Small private helpers are grouped with their parent subsystem where they implement one operation, such as interval comparison, canonical text cleanup, or HTTP serialization.

\section{Lineage and Changes from AutoCriteria}

The project was inspired by Datta's AutoCriteria repository and paper \cite{autocriteria-repo,autocriteria-paper}. The inspiration demonstrated that an LLM could structure eligibility criteria. The current application is a substantial engineering extension:

\begin{itemize}
  \item LangChain orchestration was removed in favor of direct OpenAI SDK access behind a small provider interface. This reduces framework coupling and makes prompts, schemas, token usage, and failures easier to inspect.
  \item The original long-script organization was decomposed into services, schemas, criteria-processing modules, statistical modules, and a browser presentation layer.
  \item The former standalone desktop GUI was replaced by a local web application served over HTTP. The browser is now the only supported interface.
  \item ClinicalTrials.gov API v2 retrieval and parsing allow an NCT identifier to serve as the protocol input.
  \item Extraction now includes atomic segmentation, a governed EAV terminology library, structured value and interval normalization, mapping review and reconciliation, job recovery, atomic persistence, and deterministic caching.
  \item A clinical-distance subsystem turns normalized numerical or categorical conditions into interpretable penalties for downstream statistical work.
\end{itemize}

These changes preserve the central goal of protocol-to-structure conversion while shifting the project toward a durable, auditable tool that can support trial design and population-comparison applications.

\section{Current Web Application}

\subsection{User-facing workflow}

The web interface has three tabs:

\begin{description}
  \item[Extract.] Enter an NCT ID, paste eligibility text, or do both. When text is blank, the server retrieves the trial from ClinicalTrials.gov. When text is present, it is authoritative and the NCT ID is used as its label. The user can preview deterministic segmentation or run the full AI extraction.
  \item[Clinical distance.] Compare an observed numerical value with a target criterion using a tolerance, distance scale, and condition weight. The result explains the raw distance, normalized distance, and weighted penalty.
  \item[EAV library.] Inspect the governed entities and attributes used for extraction, including library revision and content hash.
\end{description}

The criteria text box therefore has two purposes: it permits extraction of a local or unpublished protocol, and it permits an explicit override of the registry text for a supplied NCT ID. Leaving it blank selects registry retrieval.

\subsection{End-to-end extraction sequence}

\begin{enumerate}
  \item The browser posts the trial ID and optional criteria text to \code{/api/jobs/extract}.
  \item \code{EligCritExtractionService.submit} validates the input. With an empty text box it calls \code{fetch_study}; otherwise it creates a registry-shaped local source document.
  \item The source and initial job record are atomically persisted before a background thread begins.
  \item The service computes a cache fingerprint from the criteria text, configured model, and EAV-library hash. An unchanged rerun can reuse its audit and breakdown safely.
  \item Deterministic segmentation creates provenance-bearing atomic criteria. The LLM pipeline searches candidate attributes, makes a structured selection, normalizes values, and reviews the result.
  \item The completed audit is written to disk. The browser polls the job endpoint and then requests a simplified cleaned result for display.
\end{enumerate}

The cache includes the library hash so a terminology update invalidates old mappings. A failed run is not a valid cache entry and can be rerun. Each submission receives a new job ID even when the computed extraction result is reusable.

A \code{REQUIRE_NEW} row is not an extraction failure. It is a controlled terminology outcome: the clinical statement was extracted, but the governed library lacks a sufficiently equivalent attribute. Conversely, \code{CONFIRM_EXISTING} confirms the selected mapping under the automated reviewer; it does not replace clinical validation.

\subsection{Clinical-distance output}

For a scalar observation $x$, target set $T$, full-relevance tolerance $\tau$, distance scale $s>0$, and weight $w$, the numerical tool conceptually evaluates
\[
  p(x,T)=w\,\min\!\left(1,\frac{\max(0,d(x,T)-\tau)}{s}\right),
\]
where $d(x,T)$ is zero inside the target interval and otherwise is the distance to its nearest boundary. Zero means fully compatible under the policy; one times the weight is the capped maximum penalty. The JSON output includes the observed value, target, tolerance, scale, raw clinical distance, normalized penalty, weighted penalty, and diagnostic explanation. These values quantify a declared policy; they are not treatment-effect estimates or medical advice.

Errors are returned in API JSON and, for background extraction, copied into the job's \code{error} field. The exception class identifies the failure category; the text identifies the violated rule.

\toprule
Error or message & Meaning and response \\
\midrule
\endhead
Enter an NCT ID or paste eligibility criteria text & Both inputs were blank. Provide either source. \\
Invalid NCT ID / registry 404 & The identifier format is invalid or ClinicalTrials.gov has no matching study. Check the ID. \\
Registry request or timeout error & The v2 API was unavailable, slow, or returned an unexpected response. Retry after checking network access. \\
Study has no eligibility criteria & The registry record exists but exposes no criteria text usable by this pipeline. Paste the text manually if available. \\
Eligibility headings or breakdown points missing & Segmentation could not identify usable inclusion/exclusion content, or the intermediate CSV is incomplete. Inspect the source formatting and preview segmentation. \\
JSON decode/schema error & An HTTP body or LLM response was not valid JSON of the required shape. Run records identify the failing stage. \\
Existing Attribute selection must use one of the supplied top candidate \code{attribute_id} values & The model claimed an existing mapping but invented or reused an ID outside the candidates retrieved for that specific criterion. This is a guardrail failure, not evidence that the chosen ID is clinically valid. Rerun; if repeated, inspect the recorded prompt/candidates or improve the prompt/model. \\
Categorical, Sex/Gender, range, interval, or unit validation error & The selected value contradicts its schema, polarity, allowed labels, bounds, or canonical unit. Correct the input/library definition or review the LLM selection. \\
Stale library revision or SHA-256 & The governed library changed after a preview was created. Regenerate the preview before applying it; this prevents overwriting concurrent updates. \\
Attribute ID conflict/collision & Two incompatible definitions propose the same stable identifier. Reconcile or rename before applying. \\
Job has no completed audit result & The result endpoint was requested before completion or after failure. Poll job status and inspect \code{error}. \\
Missing API key / authentication error & The process did not load a valid provider credential. Put the key in the documented environment file or process environment and restart the server. \\
Rate limit, quota, or provider error & The upstream model rejected or could not complete the request. Verify quota/model access and retry; the job will be marked failed rather than silently returning partial output. \\
Request body is too large & The browser sent more than the server's 5 MB safety limit. Reduce the pasted source. \\

The saved source, job record, breakdown, checkpoints, and LLM JSONL records form the diagnostic trail. Retrying the same trial is expected to work when inputs are unchanged; a completed matching cache is reused. A repeated candidate-selection error indicates nondeterministic or invalid model output and should be addressed at the recorded mapping stage rather than by deleting the terminology library.

\section{Persistence, Recovery, and Privacy}

Runtime artifacts are organized beneath \code{runtime/eligcrit}: source documents, job records, point breakdowns, checkpoints, audits, provider records, and library snapshots. Atomic replacement protects JSON and JSONL records from partial writes. On startup, jobs left in \code{queued} or \code{running} are returned to the queue. The application binds to \code{127.0.0.1} by default, so it is locally accessible rather than a hosted multi-user system. Protocol text and model records may contain sensitive material; runtime directories and \code{.env} must remain untracked and access-controlled.

\section{Future Work}

\subsection{Fine-tuned embeddings for ``seemingly similar'' criteria}

Generic sentence embeddings overvalue lexical overlap. For example, \code{Age >= 18} and \code{Age <= 18} share nearly every token and may receive high cosine similarity, even though their admissible populations differ sharply. A clinical-criteria representation must distinguish semantic topic similarity from constraint equivalence.

The proposed model will use the current extractor as a structured supervision engine. Each criterion is represented by its clinical concept, comparator, threshold or category, unit, inclusion/exclusion polarity, and normalized interval. Development should include:

\begin{itemize}
  \item a text encoder fine-tuned with contrastive learning so criteria for the same concept remain discoverable while comparator flips, negation, exclusion polarity, and clinically material threshold changes become hard negatives;
  \item auxiliary heads for entity/attribute classification, comparator and negation classification, typed value extraction, and relation labels such as equivalent, subset, superset, overlap, disjoint, or unknown;
  \item interval-aware supervision in which structured population overlap supplies a target distance, rather than assuming that lexical cosine distance is clinically meaningful;
  \item reviewed \code{CONFIRM_EXISTING} mappings as positive pairs, reconciled aliases as additional positives, and rejected or corrected mappings as high-value negatives;
  \item retrieval followed by deterministic constraint comparison or an LLM-assisted adjudicator, with the latter required to return structured evidence rather than an unsupported scalar;
  \item calibration and abstention so ambiguous criteria are surfaced for review instead of forced into misleading proximity.
\end{itemize}

A practical loss can combine contrastive embedding loss with operator, polarity, value, and relation losses. Evaluation must be split by clinical attribute to limit leakage and must report retrieval recall, ranking quality, relation accuracy, calibration, and threshold sensitivity. A mandatory challenge set should include \code{Age >= 18} versus \code{Age <= 18}, nearby age thresholds, unit conversions, negation, and inclusion/exclusion reversals. The model should not be released if it ranks a comparator-flipped criterion as equivalent merely because the sentences are lexically similar.

The resulting representation can support duplicate detection, terminology suggestions, and clustering. More importantly, its constraint-aware distance can propagate into trial design: quantify how far a proposed eligibility rule moves from a reference population, simulate the resulting coverage and recruitment changes, and examine whether relaxing or tightening a rule changes power, sample size, or expected generalizability.

\subsection{Broader roadmap}

Additional work includes terminology links to RxNorm and ICD-10 for automatic cleaning, a separately evaluated reviewer/critic agent, adaptive dictionary updates based on embeddings and governed human approval, multi-user hosted deployment with authentication, and downstream protocol-to-design and protocol-to-analysis agents. The long-term goal is an agentic clinical-trial system that extracts eligibility constraints, validates them, compares populations, simulates trial consequences, and produces auditable statistical design artifacts while keeping clinicians and study coordinators in the approval loop.

\section{Conclusion}

The current project is no longer a single-script extraction demonstration. It is a browser-delivered, layered application with registry ingestion, atomic segmentation, structured LLM extraction, EAV governance, reviewer logic, value normalization, clinical-distance analysis, persistence, recovery, and explicit audit outputs. Its next technical challenge is to turn structured criteria into a constraint-aware population representation: one that recognizes shared clinical concepts without confusing opposite or materially different eligibility rules.
