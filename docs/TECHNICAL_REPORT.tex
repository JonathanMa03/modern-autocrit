\section{Purpose and Current Scope}

Modern AutoCrit is a standalone local browser application that extracts clinical-trial eligibility criteria from a ClinicalTrials.gov record, pasted eligibility text, or an uploaded full protocol PDF. It produces human-reviewed, validated structured criteria for protocol review, tabular analysis, cohort-definition work, and other downstream clinical data-science systems.

The current output is deliberately richer than a flat Entity--Attribute--Value record. Each atomic criterion separates its clinical domain and entity from its comparator, value, unit, interval, negation, temporal restriction, repetition, qualifier, Boolean relationship, and verbatim source. This separation prevents phrases such as ``blood pressure $>145/95$ on three occasions'' from collapsing into one opaque entity string.

The current application does \emph{not} include the retired desktop interface, the deleted clinical-distance screen, the former candidate-attribute critic/reconciliation system, or a full Chia annotation graph. Model output remains a review artifact rather than clinical ground truth. Interrupted model batches are recoverable, but recovery does not replace human review.

\section{Lineage and Design Changes}

The project began from the protocol-to-structure idea demonstrated by AutoCriteria \cite{autocriteria-repo,autocriteria-paper}. The implementation now differs in several ways:

\begin{itemize}
  \item LangChain orchestration was replaced by a small provider interface and the OpenAI SDK.
  \item The original long script was divided into registry, LLM, workflow, normalization, persistence, HTTP, and browser modules.
  \item Desktop interfaces were replaced by a local, full-width web application.
  \item ClinicalTrials.gov API v2 and full-protocol PDF ingestion were added.
  \item Human decisions are stored in timestamped JSON and CSV snapshots instead of silently changing the immutable packaged base. The current library can also be downloaded as a formatted Excel workbook for labeling and analysis.
  \item The former EAV output was replaced by a Chia-inspired structured-criterion projection. Chia distinguishes domain entities, value fields, semantic constructs, and relations; Modern AutoCrit adopts the useful distinctions in a compact tabular form without claiming full annotation-graph compatibility. See \url{https://www.nature.com/articles/s41597-020-00620-0}.
  \item Explicit interval endpoints were added for exact downstream comparison. Equivalent range expressions can therefore share one computational representation.
\end{itemize}

\section{User Workflow}

The browser contains three panels.

\begin{description}
  \item[Extraction / ingestion.] Select an NCT identifier, paste eligibility text, or upload a complete protocol PDF. PDF ingestion searches for the actual inclusion and exclusion sections and excludes later protocol material such as the SAP and schedule of activities.
  \item[Human review.] Sort the extracted rows, accept correct rows, or reject a row to edit its domain, entity, comparison, interval endpoints, semantic constructs, and Boolean relation. A corrected row must be saved before the collection can be applied.
  \item[Criteria library.] Search the immutable examples and the latest reviewed snapshot, download the combined current library as Excel, or export only validated human-reviewed records under the frozen downstream JSON contract. A confirmed reset removes generated review snapshots and returns the display to the packaged examples. Historical EAV snapshots are upgraded in memory for display; their original files are not rewritten unless the user explicitly resets the library.
\end{description}

During extraction, the progress panel reports protocol loading, the number of located source criteria, completed extraction batches, retries, semantic normalization, completion, or failure.

\section{Extraction and Normalization Sequence}

\begin{enumerate}
  \item The browser posts the selected input mode and its content to \code{/api/extractions}.
  \item The workflow validates required input. NCT mode retrieves ClinicalTrials.gov; PDF mode extracts text and locates the actual eligibility section; manual mode uses the pasted text.
  \item \code{segment_criteria()} identifies inclusion and exclusion headings, joins wrapped lines, separates numbered or bulleted criteria, splits independent semicolon-delimited cutoffs, and assigns content-derived parent-statement identifiers.
  \item Criteria are sent in bounded batches through \code{StructuredJsonAdapter} under the strict structured-criterion schema.
  \item The model separates coordinated clinical concepts and proposes domains, values, units, temporal phrases, repetition, qualifiers, negation, and AND/OR relationships.
  \item \code{normalize_rows()} rejects invented source strings, restores authoritative inclusion/exclusion labels, adds missing source rows, applies deterministic literal parsing, normalizes terminology, generates stable atomic identifiers, preserves adjacent context, and records Boolean-group membership.
  \item Automated checks attach structured findings and withhold invalid or unreviewed criteria from validated downstream export.
  \item The browser presents every row for explicit human acceptance or correction.
  \item Applying review writes cumulative, versioned JSON and CSV library snapshots to runtime storage and \code{config/}.
\end{enumerate}

\section{Structured Criterion Model}

\subsection{Domains, fields, constructs, and relations}

The compact model adapts four useful aspects of Chia:

\begin{itemize}
  \item \textbf{Domain:} observation, condition, person, device, drug, visit, procedure, or measurement.
  \item \textbf{Entity:} the canonical clinical concept only, without its cutoff or modifier.
  \item \textbf{Fields and constructs:} comparator, value, unit, interval bounds, negation, temporal restriction, repetition, and qualifier.
  \item \textbf{Relations:} derived labels such as \code{HAS_VALUE}, \code{HAS_NEGATION}, \code{HAS_TEMPORAL}, \code{HAS_MULTIPLIER}, \code{HAS_QUALIFIER}, \code{AND}, and \code{OR}.
\end{itemize}

Rows from the same source retain a shared \code{source_id}. This preserves the relationship between atomic concepts split from one sentence.

\subsection{Intervals}

A numerical rule contains nullable lower and upper bounds with separate inclusivity flags. The application also emits a readable interval string. Examples include:

\begin{longtable}{p{0.33\textwidth}p{0.22\textwidth}p{0.35\textwidth}}
\toprule
Source & Interval & Interpretation \\
\midrule
\endhead
\code{age > 18} & \code{(18, +inf)} & Open lower endpoint. \\
\code{age <= 65} & \code{(-inf, 65]} & Closed upper endpoint. \\
\code{aged 18 to 65} & \code{[18, 65]} & Closed bounded range in years. \\
\code{between 18 and 65 years} & \code{[18, 65]} & Equivalent normalized range. \\
\code{age >=18 and <=65 years} & \code{[18, 65]} & Equivalent explicit comparator form. \\
\bottomrule
\end{longtable}

Ratios such as blood pressure \code{145/95} remain literal values rather than scalar intervals. This avoids pretending that a compound measurement is one scalar cutoff.

\subsection{Illustrative structured output}

For ``Blood pressure $>145/95$ on three occasions,'' the output separates:

\begin{itemize}
  \item domain: \code{measurement}; entity: \code{Blood Pressure};
  \item comparator: \code{>}; value: \code{145/95};
  \item repetition: \code{on three occasions};
  \item relations: \code{HAS_VALUE} and \code{HAS_MULTIPLIER};
  \item verbatim source and stable source identifier.
\end{itemize}

\section{Terminology Governance}

The terminology configuration combines three legacy Modern AutoCrit maps with current additions. All legacy attribute and disease aliases are retained. Legacy entity labels are adapted into the current domains rather than treated as disease synonyms. For example, ``lab test'' maps to \code{measurement}, ``medication'' to \code{drug}, and ``diagnosis'' to \code{condition}.

Oncology coverage includes common diseases, performance measures, laboratory concepts, response concepts, and biomarkers, including NSCLC, SCLC, AML, CLL, DLBCL, ECOG performance status, Karnofsky performance status, RECIST, ANC, ALT, AST, ULN, EGFR, ALK, HER2, PD-1, PD-L1, KRAS, BRAF, BRCA1, and BRCA2.

Ambiguous short forms such as \code{ALL}, \code{MM}, \code{CR}, \code{PR}, \code{SD}, and \code{PD} are exact-match only. Thus an extracted entity equal to \code{ALL} can normalize to Acute Lymphoblastic Leukemia without rewriting the ordinary phrase ``all patients.''

\section{Outputs and Their Meaning}

\subsection{Job record}

Each submission creates \code{runtime/criteria/jobs/<job_id>.json}. It contains the job, trial, and protocol identifiers; source version, URI, retrieval time, and protocol hash; input mode; timestamps; status; stage; progress; error; source items; completed model batches; checkpoint rows; final rows; and an ordered event log.

\begin{longtable}{p{0.22\textwidth}p{0.70\textwidth}}
\toprule
Status & Meaning \\
\midrule
\endhead
\code{queued} & The durable job record exists and its worker has not started. \\
\code{running} & Ingestion, model extraction, or semantic normalization is active. \\
\code{completed} & Structured rows are available for human review; they are not yet governed additions. \\
\code{failed} & The job stopped and \code{error} contains the immediate exception. \\
\bottomrule
\end{longtable}

\subsection{Review rows}

Every row contains stable criterion and parent-statement identifiers, protocol/source version, source and surrounding context, Boolean-group membership and atom order, criterion type, domain, entity, comparison fields, semantic constructs, model extraction confidence, validation findings, human-review status, and validated-export readiness. Human rejection opens editable semantic fields; saving distinguishes a corrected row from one accepted unchanged.

\subsection{Criteria-library snapshots}

Applying review creates timestamped \code{criteriaLibrary} JSON and CSV snapshots. JSON is authoritative and uses structured-criteria schema v4; CSV provides a convenient tabular export. Copies are written to \code{runtime/criteria/libraries/} and \code{config/}; generated config copies are ignored by Git.

The Criteria Library panel also exposes \code{/api/library.xlsx}. This endpoint generates a workbook from the immutable base plus the latest reviewed snapshot without changing either source. The main worksheet contains normalized fields, source evidence, frozen headers, and filters; a second worksheet explains the fields for human labelers.

The \code{/api/validated-export.json} endpoint emits only rows with complete provenance, accepted or corrected human review, and no blocking validation findings. Its frozen schema identifier is \code{modern-autocrit.validated-criteria.v1}; a copy is retained under \code{runtime/criteria/exports/}.

The reset endpoint requires browser confirmation and removes generated \code{criteriaLibrary_*} and historical \code{eavLibrary_*} JSON/CSV snapshots from the runtime library directory and \code{config/}. It does not remove extraction job records, unrelated files, or \code{base_criterion_library.json}. The immutable records use trial marker \code{EXAMPLE} and include deliberately difficult cases for interval boundaries, sex wording, ambiguity, temporal and repeated measurements, exceptions, and compound logic.

The application can read historical \code{eavLibrary_*.json} snapshots. It converts their comparator/value form into the richer representation in memory and does not mutate the old file. The first newly applied review carries the upgraded records into a v4 criteria snapshot. Legacy records without adequate provenance remain visibly ineligible for validated export.

\section{Errors and Operational Interpretation}

\begin{longtable}{p{0.35\textwidth}p{0.57\textwidth}}
\toprule
Error or symptom & Meaning and response \\
\midrule
\endhead
Missing API key & Add \code{OPENAI_API_KEY} to the repository-root \code{.env} and restart. \\
Invalid or missing NCT ID & Check the identifier and registry availability. \\
No eligibility criteria segmented & Headings or list formatting were not recognized; use manual text or inspect the PDF section. \\
PDF section not recognized & The document lacks recognizable inclusion/exclusion headings or is image-only. OCR is not currently performed. \\
Structured response failure & The provider did not return the strict schema after retries. Completed batches remain checkpointed; resume the job or rerun its manifest. \\
Request body too large & The server accepts at most 75 MB JSON bodies and the browser limits PDF selection to 55 MB. \\
Review cannot be applied & Every row must be accepted or corrected and pass the automated interval, negation, unit, temporal, repetition, and compound-scope checks. \\
Port already in use & Stop the prior process or launch with a different \code{--port}. \\
Legacy snapshot shown & No v4 snapshot exists yet; the newest historical file is being upgraded in memory. Apply a reviewed run to create v4 files. \\
\bottomrule
\end{longtable}

\section{Current Limitations}

\begin{itemize}
  \item Jobs and completed batches are persisted and resumable, but prompts and raw model responses are not yet written as a complete audit trail.
  \item PDF extraction is text-based and does not OCR scanned protocols.
  \item The criteria library stores reviewed trial assertions. A future governed concept layer should separate reusable concept definitions from trial-specific constraints.
  \item Terminology normalization is a curated alias system, not an ontology service. RxNorm, LOINC, OMOP, NCIt, or ICD links are not yet assigned.
  \item The representation is inspired by Chia but does not implement arbitrary nested annotation graphs or executable patient queries.
  \item Cross-trial distances, calibration, and learned representations are outside this extractor. The validated schema can supply their inputs.
\end{itemize}

\section{Optional MetricSpace Integration}

The structured output permits distinct comparison channels:

\begin{itemize}
  \item canonical-entity agreement and governed synonymy;
  \item domain compatibility;
  \item exact interval relations, including equivalence, subset, superset, overlap, and disjointness;
  \item comparator direction and endpoint sensitivity;
  \item negation, inclusion/exclusion polarity, temporal scope, repetition, qualifier, and Boolean-structure disagreement;
  \item embedding or LLM judgment for residual clinical semantics that cannot be resolved structurally.
\end{itemize}

Reviewed human corrections can become labeled supervision. A future agentic layer can select structural comparison for exact constraints, retrieve terminology candidates, invoke an embedding model for paraphrases, request LLM adjudication for ambiguity, reconcile disagreement, quantify uncertainty, and escalate unresolved cases.

Modern AutoCrit is intentionally near feature freeze. For a MetricSpace study, remaining work is operational data production: select trial cohorts, run recoverable extraction, complete human review, resolve validation blockers, and freeze versioned validated exports. Raw model audit records, ontology identifiers, and a separate governed concept layer remain possible later improvements rather than prerequisites for that downstream project.

\section{Conclusion}

Modern AutoCrit is now a standalone browser-delivered protocol eligibility extractor and human-review tool whose output is designed for analysis and reuse rather than display alone. Its v4 library schema and frozen validated-criteria v1 handoff preserve identifiers, source versions, context, quantitative intervals, semantic constructs, Boolean scope, review state, automated validation, and readiness. Specialized comparison or representation-learning systems can consume this output without being required to understand Modern AutoCrit internals.
